Sieve of Eratosthenes

An interactive, educational rhythm game and audio-visual mathematical demonstration of the Sieve of Eratosthenes, built with Flutter for Web and Android.

1. Project Overview & Motivation

The Sieve of Eratosthenes is an ancient algorithm dating back to the 3rd century BCE, formulated by Greek mathematician and chief librarian of Alexandria Eratosthenes of Cyrene. It is one of the most elegant and efficient algorithms for finding all prime numbers up to any limit by systematically marking multiples of each discovered prime as composite.

This project transforms the algorithm into a living, rhythmic, audio-visual experience and number-reflex game:

  • The Sieve Rhythm Clock: The app counts forward at an adjustable tempo (0.2 Hz0.2\text{ Hz} to 5.0 Hz5.0\text{ Hz}, default 1.0 Hz=60 BPM1.0\text{ Hz} = 60\text{ BPM}).

  • Atomic Prime Tones: Each discovered prime is assigned an atomic musical tone derived from the natural overtone series (2=C3,3=G3,5=E4,7=B4♭,11=F5♯,13=A52 = C_3, 3 = G_3, 5 = E_4, 7 = B^\flat_4, 11 = F^\sharp_5, 13 = A_5). Primes are silent when first discovered and only sound when they are part of a composite.

  • Composite Harmonic Chords: When the rhythm reaches a composite number NN, it sounds all of its prime factors simultaneously as a musical chord (e.g. 6=2×36 = 2 \times 3 plays an open fifth chord C−GC - G; 30=2×3×530 = 2 \times 3 \times 5 resolves into a complete C Major triad C−E−GC - E - G).

  • Prime Multiplicities (Powers) as Octaves: Numbers with repeated factors (4=22,8=23,12=22×34 = 2^2, 8 = 2^3, 12 = 2^2 \times 3) layer higher octave harmonics, enriching the timbre (toggleable in the top app bar).

  • Continuous Proximity Waves: The bottom dashboard displays real-time progress bars for each discovered prime using the continuous triangle wave metric:

    f(t)=|2⋅((speed⋅t)(mod⁡p))p−1.0|f(t) = \left| 2 \cdot \frac{((\text{speed} \cdot t) \pmod p)}{p} - 1.0 \right|

smoothly peaking at 1.01.0 exactly at multiples of pp and falling to 0.00.0 at midpoints.

    • Prime power multiplicity decomposition and formatting (4⟹22,12⟹22×34 \implies 2^2, 12 \implies 2^2 \times 3).

    • Zero-drift beat generator using Stopwatch + TickerProvider to provide continuous sub-millisecond fractional time N(t)N(t).

    • Continuous triangle-wave proximity metric calculation.

    • Curated colors and pitch frequencies for primes using golden-ratio algorithmic HSL color distribution.

    • Web Audio API polyphonic engine with multi-octave acoustic grand piano samples (C3, G3, C4, E4, C5, A5, C6 at ~1.2MB total).

    • Realtime pitch-shifting via playbackRate with seamless fallback to resonant overtone oscillators when offline.

    • Primes remain silent when first discovered, sounding only as factors of subsequent composite numbers.

    • Acoustic balancing boosting primes 2 (+35%+35\%) and 3 (+20%+20\%) for a strong bass root and fifth.

    • Dynamics compressor preventing digital distortion/clipping.

    • Master volume slider with percentage tooltip and instant mute/unmute toggle.

    • Harmonics toggle (defaults to OFF) to switch between full octave harmonics vs. fundamental notes.

    • Silent “Guess Next (#N+1)” reflex action button and keyboard hotkey (Spacebar).

    • Scoring system with +1+1 for correct prime guesses and −1-1 penalty for composite guesses.

    • Persistent high score, best prime streak, accuracy meter, and career statistics via SharedPreferences.

    • Visual guess history border indicators on the number grid (green = correct, red = incorrect, amber = pending).

    • Dedicated Player Stats & Records modal with career metrics and reset option.

    • Dedicated How to Play dialog loading markdown rules from doc/rules.md.

    • Keyboard navigation: P (play/pause), Spacebar (guess next), Left/Right arrows (tempo ±0.2 Hz\pm 0.2\text{ Hz}), Up/Down arrows (smooth scroll).

    • Firebase Realtime Database backing lightweight synchronized rooms (fredgc-sieve-default-rtdb).

    • Strict Quota Clamping: Max 10 rooms project-wide, max 10 players per room (10×10=10010 \times 10 = 100 connections max, strictly within Spark free tier limits).

    • Inactivity Auto-Pruning: Automatic cleanup of rooms inactive for ≥10\ge 10 minutes.

    • QR Code & Shareable Link: Dynamic QR codes via qr_flutter and one-click URL sharing (/?room=CODE) with automatic query parameter detection on load.

    • Dropout & Reconnection Recovery: Persistent session tokens in local storage with a 3-minute grace period allowing disconnected players to rejoin without score or streak loss.

    • Synchronized Beat Clock & Catch-Up: Clock synchronization using /.info/serverTimeOffset and timestamp alignment to eliminate timer drift; late-joining or reconnecting guests automatically catch up to the host’s exact beat.

    • Host Authority & Room Playback Sync: Only the room host can pause, resume, reset, or change tempo, synchronizing changes in real-time across all clients. Guests have transport buttons replaced by a dedicated “Leave Room” button and a locked tempo display, preventing accidental desync.

    • Live Scoreboard HUD: In-game multiplayer leaderboard showing all players, scores, streaks, prime predictions, and a quick-leave action.

4. Development & Running

Prerequisites

  • Flutter SDK (3.24+ recommended)

  • make and Pandoc (for compiling documentation)

Forking and Cloning

  1. Fork the repository on GitHub to your account.

  2. Clone your fork locally:

    git clone https://github.com/<your-username>/sieve.git
cd sieve

  3. Install Flutter dependencies:

    flutter pub get

  4. Compile documentation assets:

    make docs

Starting Development Environment

./setup.sh

Running Locally

# Debug mode on local port
./run-local-server.sh

# Or release build local server
./run-local-release.sh

Building Assets & Documentation

make ASSETS

Running Tests & Static Analysis

flutter test
flutter analyze

Staging to Firebase Hosting

make stage

Deploys the web application to the staging channel on Firebase Hosting for project fredgc-sieve.
