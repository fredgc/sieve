1. Project Purpose & Core Architecture

The Sieve of Eratosthenes app transforms prime number discovery into an interactive audio-visual rhythm experience:

  • Numbers count forward at an adjustable tempo (0.2 Hz0.2\text{ Hz} to 5.0 Hz5.0\text{ Hz}).

  • Discovered primes are assigned unique atomic musical notes from the overtone series and distinct vibrant colors; primes are silent when first discovered and only sound when they are part of a composite.

  • Composite numbers sound all their prime factors simultaneously as musical chords.

  • Prime powers (4=22,8=23,12=22×34 = 2^2, 8 = 2^3, 12 = 2^2 \times 3) layer higher octave harmonics.

  • Bottom proximity dashboard renders continuous triangle waves:

    f(t)=|2⋅((speed⋅t)(mod⁡p))p−1.0|f(t) = \left| 2 \cdot \frac{((\text{speed} \cdot t) \pmod p)}{p} - 1.0 \right|

smoothly peaking at 1.01.0 at multiples and reaching 0.00.0 at midpoints.

3. Current Implementation Status

Completed (Stages 1, 2, 3 & 4)

  • Mathematical Sieve Core: Verified deterministic factorization, prime caching, and continuous proximity triangle wave calculation in lib/models/sieve_engine.dart.

  • Zero-Drift Beat Clock: Implemented lib/models/beat_clock.dart using Stopwatch + TickerProvider to prevent timer drift and provide continuous fractional time N(t)N(t).

  • Polyphonic Acoustic Web Audio Synthesizer & Piano Soundfont: Implemented in lib/models/audio_engine_web.dart using Web Audio API:

    • Acoustic Grand Piano Sample Library: Multi-octave piano audio anchors (C3, G3, C4, E4, C5, A5, C6 at ~1.2MB total) pre-decoded into memory with zero-latency realtime pitch shifting via playbackRate.

    • Seamless Fallback: Pure harmonic oscillators and resonant overtones activate seamlessly if sample buffers are loading or offline.

    • Primes are silent when first discovered, sounding their musical tones only when they are factors of subsequent composite numbers.

    • Composite chords sounding all prime factors simultaneously with octave harmonics for powers (4=22,8=234 = 2^2, 8 = 2^3).

    • Acoustic Balancing: Primes 2 (+35%+35\%) and 3 (+20%+20\%) are boosted in gain so the fundamental bass root (C3C_3) and perfect fifth (G3G_3) provide a strong, warm harmonic anchor.

    • Configurable Harmonics Checkbox in AppBar (defaults to OFF): toggle between full octave harmonics for prime powers vs. single fundamental note.

    • Master dynamics compressor preventing digital distortion/clipping.

    • Autoplay policy unlock handling on user interaction (Play, Step, Reset, Mute, or Tile click).

    • Master Volume Slider & Mute Toggle: Interactive volume slider with percentage tooltip positioned directly alongside dynamic mute/unmute control in AppBar.

  • Keyboard Navigation & Hotkeys:

4. Build, Test & Deployment Workflow

Build and Asset Automation (Makefile)

The project uses make targets to coordinate asset compilation and builds:

  • make docs: Compiles user markdown docs from doc/*.md into assets/*.html and developer docs (plan.md, README.md, GEMINI.md) into assets/dev/*.html via pandoc.

  • make ASSETS: Generates icons, favicons, version metadata, and docs.

  • make test: Runs standard Flutter unit, widget, and ARB localization parity tests on every commit (flutter test --exclude-tags release_audit). Fast execution (~2-5 seconds).

  • make audit: Runs exhaustive pre-release accessibility and multi-locale layout audits (flutter test test/audit_test.dart). Tests all supported locales, compact mobile/tablet/desktop viewports, 1.5x/2.0x font scaling, and WCAG AA guidelines (labeledTapTargetGuideline). Required automatically by make stage-release and make release.

  • make stage: Builds web app with debug flags and deploys to Firebase staging channel.

  • make stage-release: Builds production web bundle and runs firebase_stage.pl.

  • make release: Rolls version number (--release), runs full build, and deploys via Firebase (sieve.gchouse.org).
